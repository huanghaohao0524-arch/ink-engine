# 墨引擎用户路径 QA 清单

目标：每次进入 UI 美化或继续加功能前，先确认核心写作闭环没有断。

## 1. 新建书路径

- 选择写作库。
- 新建书籍，选择平台，输入一句脑洞。
- 开始 AI 五问。
- 回答基础 5 问后，确认出现检查点。
- 点击生成项目包。
- 确认能创建标准书籍目录并进入项目准备/写作页。

通过标准：
- 项目资料里至少有平台规则、题材规则、核心设定、主角卡、总纲、追踪资料。
- 用户不会被迫理解底层任务卡或状态机。

## 2. 精修写下一章路径

- 进入一本已有项目。
- 选择“精修”。
- 点击“写下一章”。
- 等待生成完成。
- 查看结果判断。
- 应用候选。

通过标准：
- 软件自动完成新建章节、细纲、正文候选。
- 正文在应用前不会直接覆盖编辑器。
- 应用后状态沉淀资料有更新。

## 3. 人话反馈路径

- 在“哪里不满意”输入框写：网游味不够、主角太被动、节奏太慢等自然语言。
- 点击“按我的反馈调整”。
- 查看候选和结果判断。
- 应用候选或打开调试详情检查影响范围。

通过标准：
- 用户只需要说问题，不需要选择改细纲、改正文还是改设定。
- 需要全篇修复时，调试详情里仍有资料修复入口。

## 4. 连写模式路径

- 选择“连写”。
- 设置章数，例如 5。
- 点击“写下一章”。

通过标准：
- 每章自动写入正文并生成快照。
- 如果某章出现门禁或质量问题，会暂停并标记需复核。
- 用户能切回精修处理问题章。

## 5. 无脑模式路径

- 选择“无脑”。
- 设置较大章数，例如 10 到 20。
- 点击“写下一章”。

通过标准：
- 一般警告不打断流程。
- 失败或接口中断时不丢失已完成章节。
- 结果列表能看到哪些章节需要复核。

## 6. 调试与成本路径

- 展开“调试详情”。
- 查看最近任务、步骤耗时、成本摘要、AI 调用记录。
- 对失败任务尝试单步重试。

通过标准：
- 普通用户默认看不到复杂概念。
- 开发调试时能定位失败步骤、耗时、输入/输出规模和缓存 key。

## 自动回归命令

```bash
npm run smoke:core
npm run lint
npm run build
```

发版前再运行：

```bash
npm run dist:win
```
